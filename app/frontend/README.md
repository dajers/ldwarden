# ldwarden — фронтенд

Статический SPA без сборки и зависимостей: узлы с пинами и проводами, панорама и масштаб,
сакура-палитра, живое выполнение сценария и разбор находок. Работает с реальным Flask-бэкендом
LDWarden, а при его недоступности автоматически откатывается на встроенный мок-движок.

## Запуск

```bash
cd /home/dajers/Documents/LDWarden
./start.sh
```

Открыть <http://127.0.0.1:8000/> — Flask раздаёт этот SPA с того же origin, CORS не нужен.

Демо-режим: <http://127.0.0.1:8000/?demo=1> — загружает пресет «Перед релизом» и запускает его.

Отдельный статический сервер тоже возможен (`python3 -m http.server`), но тогда API будет
недоступен и интерфейс останется в mock-режиме.

## Как собрать сценарий

- **Узел из палитры** перетаскивается на холст в точку курсора (или добавляется по клику в центр).
- **Провод**: потяните от пина к пину. Кружки — данные, треугольники — поток выполнения.
  Во время протяжки совместимые пины подсвечиваются, несовместимые соединения отклоняются.
- **Перетаскивание узла** — за шапку или тело; координаты прилипают к сетке.
- **Панорама** — правая кнопка мыши по холсту; **масштаб** — колесо мыши, кнопки `−` / `+` / «Вписать».
- **Выделение** — ЛКМ по узлу; `Shift/Ctrl/Cmd + ЛКМ` — добавить/убрать; ЛКМ по пустому холсту — рамка для нескольких узлов.
- **Перемещение** — тяните любой выбранный узел: двигается вся группа.
- **Удаление** — `Delete` (выбранные узлы или провод) либо крестик на узле.
- **Параметры** — в панели справа; она открывается по выбору узла.
- **Пресеты**: кнопка «Пресеты» открывает меню со встроенными («Быстрый аудит», «Только секреты», «Перед релизом»), своими пресетами и пунктом «+ Создать пресет». Свои пресеты хранятся в `localStorage` (`sakura.presets.v1`), секреты в них маскируются.

Во время запуска реальные статусы приходят из бэкенда по SSE: узел получает
`выполняется` → `готово` / `не выполнялся` / `ошибка`, по проводам бежит пунктир,
в узле появляется чип с результатом шага.

## Ноды управления

| Нода | Что делает |
| --- | --- |
| «Условие» | сравнение значения из контекста, ветки «Да» / «Нет» |
| «Своё условие» | выражение пользователя: `critical >= 1`, `not anyPath('/test/')`, `matches(target, "release-*")` |
| «Регулярка» | ищет шаблон по пути, классу, сообщению или категории находок; ветки «Совпало / Не совпало» |
| «Разветвитель» | один вход → три ветки, выполняются все |
| «Собиратель» | ждёт все подключённые входы и продолжает поток один раз |

Выражение для «Своего условия» разбирается безопасным парсером на бэкенде (без `eval`), а в mock-режиме
и в подсказке инспектора — таким же парсером на JS. Переменные: `total`, `critical`, `high`, `medium`,
`low`, `secret`, `sca`, `sast`, `hasCritical`, `hasSecrets`, `target`; функции: `anyPath`, `anyClass`,
`anyMessage`, `matches`, `contains`, `count`.

## Любая папка как цель

В ноде «Репозиторий» можно указать абсолютный путь к любой папке — бэкенд просканирует все
текстовые файлы внутри (с учётом исключений вроде `node_modules`, `.git`, `build`). Ограничение
Ограничения по каталогам больше нет: сканировать можно любую папку, к которой есть доступ у процесса.

## Цвета узлов и связей

- **Узел**: в инспекторе есть палитра «Цвет узла» — как в теме, красный, оранжевый, зелёный, синий,
  фиолетовый или свой цвет. Хранится в `node.color`, уходит на сервер в `data.color` и переживает перезагрузку.
- **Связь**: клик по проводу открывает палитру; цвет хранится в `edge.color` и не перебивается темой.
- Линии рисуются с подложкой цвета холста и стрелкой у входного пина; наконечник окрашивается в цвет связи.

## Что синхронизируется с бэкендом

- Черновик графа автоматически сохраняется в `localStorage` и с задержкой — на сервер
  (`POST /api/workflows` или `PUT /api/workflows/{id}`).
- При первом открытии подгружается пользовательский workflow с сервера; если его нет —
  шаблон `tpl-full-audit`.
- Пресет создаёт новый workflow; редактирование шаблона приводит к созданию копии
  (`/api/templates/{id}/clone`), чтобы не портить библиотеку.
- Запуск: `POST /api/workflows/{id}/runs`, затем SSE `GET /api/runs/{id}/stream`.
- Git-источник: в узле «Репозиторий» укажите HTTPS-URL; на сервере задайте `LDWARDEN_ALLOWED_GIT_HOSTS`, для приватных репозиториев — `LDWARDEN_GIT_TOKEN` и `LDWARDEN_GIT_USERNAME`.
- Отмена: `POST /api/runs/{id}/cancel`.
- Результаты (находки, AI, уведомление, отчёт) читаются из `/api/runs/{id}`,
  `/findings`, `/ai`, `/report`.
- История последних запусков пока хранится в браузере; на сервере полная история
  доступна через `/api/runs`.

## Соответствие моделей

Внутренняя модель фронтенда оптимизирована под рисунок, поэтому адаптер `js/api.js`
переводит её в формат бэкенда:

| Фронтенд | Бэкенд |
| --- | --- |
| `source.repo` | `source.target` |
| `scan.secret` | `scan.secrets` |
| `ai.explain` | `ai.analyze` |
| `logic.branch` | `logic.if` |
| `control.gate` | `control.severity_gate` |
| `notify.send`, `scan.sca`, `scan.sast`, `report.build`, триггеры | без изменений |

Параметры тоже нормализуются: `minSeverity` → `min_severity`, `chatId` → `chat_id`,
`dryRun` → `dry_run`, `formats` и cron-подписи — в значения бэкенда. Данные-связи
(кружки `findings`, `summary`, `payload`) остаются визуальными: бэкенд передаёт общий
контекст между шагами, поэтому для выполнения нужны exec-связи.

## Telegram

В AI-ноде можно ограничить провайдера, число находок, потоки CPU (`threads`, по умолчанию 4) и таймаут (45 с). Для локальной модели меньше потоков = ниже нагрузка на CPU, но медленнее; после таймаута включается fallback.

В инспекторе `notify.send`:

- канал **Telegram**;
- `Токен` → `bot_token`, `Chat ID` → `chat_id`;
- `Токен` и `Chat ID` можно оставить пустыми, если они заданы в `.env`
  (`LDWARDEN_TELEGRAM_BOT_TOKEN`, `LDWARDEN_TELEGRAM_CHAT_ID`) или чат подключён
  через `/api/telegram/connect`;
- `Dry-run` — проверить сценарий без реальной отправки;
- `Приложить отчёт` — отправить Markdown-отчёт целиком;
- кнопка **«Подключить Telegram»** открывает deep-link, ждёт Start и подставляет `chat_id`.

## Темы оформления

В шапке — круглая кнопка с пальмой. Темы: **Сакура**, **Чёрно-белый** (тёмный, основной цвет — чёрный), **Варден**.
Выбор хранится в `localStorage` (`sakura.theme`) и применяется до первой отрисовки.

## Цвета связей

Клик по проводу открывает палитру: цвет темы, красный, оранжевый, жёлтый, зелёный и
свой цвет. Выбранный цвет хранится в ребре (`edge.color`) и переживает перезагрузку.

## API-контракт (фактический)

```
GET  /api/workflows?include_templates=1
POST /api/workflows                  { name, graph }
PUT  /api/workflows/{id}             { name, graph }
POST /api/workflows/{id}/runs        { wait: false }
GET  /api/runs/{id}/stream           SSE
POST /api/runs/{id}/cancel
GET  /api/runs/{id}?reports=1
GET  /api/runs/{id}/findings
GET  /api/runs/{id}/ai
GET  /api/runs/{id}/report?format=md|json|sarif
```

События бэкенда (`run.started`, `node.started`, `node.finished`, `finding`,
`run.finished`, `run.failed`, `run.cancelled`) адаптер переводит в события интерфейса
(`run.started`, `node.started`, `node.done`, `findings`, `run.done`, `run.error`).

## Горячие клавиши

- `⌘/Ctrl + Enter` — запустить или остановить проверку
- `Delete` / `Backspace` — удалить выбранный узел или провод
- `Esc` — закрыть результаты или окно истории
- колесо — масштаб, правая кнопка мыши — панорама, ЛКМ по фону — рамка выделения

## Ограничения

- Если бэкенд недоступен, остаётся mock-режим; данные не уходят на сервер.
- History drawer хранит последние 10 запусков в браузере, хотя серверная история полнее.
- Секреты нод на время работы браузера могут находиться в `localStorage`; на сервере
  они шифруются. Для продакшена стоит очищать локальный снапшот после синхронизации.
- Связи данных визуальные; полноценная типизация data-портов пока не реализована.
